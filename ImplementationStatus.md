# Implementation status

Audit of this repository against [NORTH_STAR.md](NORTH_STAR.md). Written from the code as it exists, not from the vision document.

This is a working FastAPI Mission Control MVP, not yet the full north star. The app is runnable; durable runtime, model routing, policy, tools, workers, and the truthful live UI have broad test coverage.

## How to read this

- **DONE** means it works in this codebase today.
- **PARTIAL** means a real seed exists but is far from the north-star behavior.
- **MISSING** means not present in a form that can be extended without new work.
- **BROKEN** means present but incorrect, unused, or actively misleading.
- Classification records *what* failed. `RATE_LIMIT` and `TIMEOUT` are retried with bounded backoff against the same provider. `PROVIDER_OUTAGE` (or an unconfigured/unavailable primary) may use the next catalog candidate (OpenRouter when `OPENROUTER_API_KEY` is set; xAI when `XAI_API_KEY` is set; Anthropic when `ANTHROPIC_API_KEY` is set; Mistral when `MISTRAL_API_KEY` is set; Gemini when `GEMINI_API_KEY` is set; Cohere when `COHERE_API_KEY` is set; DeepSeek when `DEEPSEEK_API_KEY` is set; Together when `TOGETHER_API_KEY` is set; Groq when `GROQ_API_KEY` is set; Fireworks when `FIREWORKS_API_KEY` is set; Azure OpenAI when `AZURE_OPENAI_API_KEY`, `AZURE_OPENAI_ENDPOINT`, and `AZURE_OPENAI_DEPLOYMENT` are set; Perplexity when `PERPLEXITY_API_KEY` is set; Bedrock when `BEDROCK_API_KEY` or `AWS_BEARER_TOKEN_BEDROCK` is set; Hugging Face when `HUGGINGFACE_API_KEY` is set; Cerebras when `CEREBRAS_API_KEY` is set; SambaNova when `SAMBANOVA_API_KEY` is set; Vertex AI when `VERTEX_API_KEY` and `VERTEX_PROJECT` (or `GOOGLE_CLOUD_PROJECT`) are set; local Ollama when `OLLAMA_MODEL` or `OLLAMA_BASE_URL` is set; local vLLM when `VLLM_MODEL` or `VLLM_BASE_URL` is set; local llama.cpp when `LLAMACPP_MODEL` or `LLAMACPP_BASE_URL` is set). ## DONE

- Durable `WorkQueue` negative completion: the live lease owner can report a classified terminal `job.failed` or atomically schedule `job.retry_scheduled` with a not-before `available_at`. Foreign, expired, wrong-mission, pending, and already-terminal writes fail closed; the lease is released in the same transaction, failure state survives restart, and a retry increments the attempt only when reclaimed.
- Bounded out-of-process queue execution (`ProcessWorkerPool` in `app/workers.py`, #66): trusted importable handler references run in fixed Python `spawn` processes, each opening its own SQLite `Store` / `WorkQueue`. Workers claim durable jobs, atomically heartbeat both lease and work-item expiry, complete only as the live owner, record real handler failures, and reclaim expired work. Handlers may receive a trusted `WorkerContext` (Store/queue/owner/database path) outside the payload; one-argument handlers remain compatible. Classified runtime/provider failures are retained on `job.failed` instead of being flattened.
- Opt-in durable specialist task dispatch (`app/mission_jobs.py`): `SWARM_PROCESS_WORKERS=1..8` makes `SwarmRuntime` enqueue deterministic `mission.agent_task` work and wait/reconcile through `WorkQueue`; FastAPI lifespan starts the fixed pool after recovery scheduling and stops it after mission suspension. Payloads are exactly mission/task/agent UUIDs. Each child reconstructs `SwarmRuntime`, providers, tools, policy, and credentials from its inherited trusted process environment/configuration. Invalid/extra payload fields, missing or inconsistent durable entities, unconfigured providers, mismatched results, lost leases, and terminal human controls fail closed. The controller/meta-orchestration loop remains in the web process; the existing in-process specialist path remains the default when `SWARM_PROCESS_WORKERS=0` (default).

- `SwarmRuntime`: spawn agents, assign one pending task per new specialist, call the controller, stop a mission or all missions, and simulate payments (`app/runtime.py`). By default specialist tasks still run as in-process asyncio work; with the bounded-pool opt-in they use durable process jobs while controller decisions remain in-process. `MissionStatus.WAITING` is persisted and emitted as `mission.waiting` while that work runs, then `mission.running` before the next decide. `wait` with no pending/running tasks still raises `PolicyError` (`INVALID_OUTPUT`). The HUD applies `mission.waiting` / `mission.running` onto the status chip (not only terminal events). Invalid, terminal, and unconfigured transitions fail closed.

## TECH DEBT

- `SwarmRuntime.run` is the orchestrator, factory, task engine, and failure handler in one module. Verification is extracted to `app/verifier.py` + `OpenAIProvider.verify` + bounded `app/evidence.py` runners; do not grow the runtime loop further.

- Event *payloads* are still free-form dicts. `EventType` now catalogs names; typed payload models can come with the next observability expansion.
- `LLMProvider` remains the controller+worker behavior interface layered over the lower-level `ModelProvider`. `ModelRouter` is the selection seam; do not add provider conditionals to the runtime.
- SQLite schema is versioned (`app/migrations.py`, currently v4). Future column adds belong in `Migration(version=N+1)` using `add_column_if_missing`. SQLite may keep an ADD COLUMN from a failed attempt; do not stamp `schema_migrations` unless the upgrade finished. Destructive rename/drop still needs an explicit rebuild migration.
- Windows-only credential save path; Linux/cloud must use `OPENAI_API_KEY`.
- UI is vanilla JS modules (`control.js`, `state.mjs`, `control.css`). North star allows preserving this stack. Do not replace with React/Pixi in an early slice.
- Default model id `gpt-6-astra` is environment-specific; keep it overridable via `SWARM_MODEL`.
- No packaging beyond `pyproject.toml`; no Dockerfile. GitHub Actions CI (`lint` / `typecheck` / `test`) runs on PRs and `main`. Ruff is a narrow syntax/undefined-name gate that passes current main; mypy is not a gate (would require ModelProvider/runtime annotation churn).
